# Как это работает
1. Прокси получает запрос от клиента. Как правило это https, поэтому прокси знает только хост, но не знает полный путь к запрашиваемому ресурсу.
2. Прокси пробует получить ip адрес (DNS). Если адрес не резолвится, соединяет клиента с сервером напрямую и помечает домен статусом FAILED.
3. Прокси проверяет нужный порт сервера. Если порт недоступен (скорее всего блокируется ip), прокси соединяет клиента с сервером напрямую и помечает домен статусом FAILED.
4. Поскольку путь к запрашиваемому ресурсу неизвестен, прокси скачивает `/` (следуя редиректам). Если получилось, соединяет клиента с сервером напрямую и помечает домен статусом DIRECT.
5. Если ресурс недоступен, прокси запускает перебор стратегий для доступа к серверу. Если стратегию подобрать не удалось, прокси соединяет клиента с сервером напрямую и помечает домен статусом FAILED.
6. Полученый в п. 4 контент парсится на наличие ссылок (внешние и внутренние). Ссылки проверяются на доступность, используя стратегию из п. 5. Для всех найденных недоступных ссылок делается подбор стратегии (один раз для каждого домена). Для внешних доменов происходит полная проверка (с п. 2), но уже с указанием пути к ресурсу. Для текущего домена происходит только перебор стратегий.
7. Если поиск стратегии завершился удачей, прокси перенаправляет трафик через ciadpi, и помечает домен статусом PROXY. В противном случае соединяет клиента с сервером напрямую и помечает домен статусом FAILED.
8. Вся полученная информация кэшируется. Домены со статусом DIRECT в файле `cache/direct.txt`, со статусом PROXY в `cache/rules.txt`, со статусом FAILED в `cache/failed.txt`.
9. У каждого статуса есть время устаревания (TTL), по истечении которого происходит перепроверка домена. Устаревшие (когда-то успешные) стратегии сохраняются в кэше в файле `cache/history.txt`.
